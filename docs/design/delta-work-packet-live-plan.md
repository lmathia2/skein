# Delta work packets and terminating review: implementation and live gate

Date: 2026-09-14. Baseline evidence: [the eight-task DeepSWE comparison](../experiments/memory-heldout-8-20260914.md) and [the context brief](../experiments/memory-navigation-context-brief-20260914.md).

## Outcome and ownership

Reduce newly uncached context at outer work-batch boundaries without losing task requirements, steering, provenance, live PTC reuse, or independently verified completion. `app/agent/workflow.py` owns boundary/decision control; `harness/core/orchestration` owns packet serialization and deltas; `harness/adapters/adk/context.py` owns evidence-navigation projection; the canonical event stream owns publication and replay. No new model tool, memory database, or verifier authority is introduced.

## Frozen implementation group

1. **Review control.** Keep the single bounded counterexample-review cell. After its yield, require one structured verify/fix/block decision. Do not force `phase=review` or route `CONTINUE` after the decision has selected verification, and do not start another identical review on an unchanged workspace. New defects or failed independent verification may reopen implementation/review; malformed or unsupported claims remain rejected and cannot be auto-promoted.
2. **Section deltas.** The first work packet exposes the full required contract. Each later packet compares deterministic section snapshots against the last model-exposed packet and appends only changed task fields, new evidence/navigation entries, newly delivered steering, and other changed sections. Repeated skills, project manifest, conversation, and overlapping recent events are omitted. The delta includes deletions/invalidation explicitly. Required scope and safety control is never dropped merely because a previous packet existed.
3. **Navigation deltas.** Keep `work_batch_navigation@7` full snapshots as the compatibility baseline and publish `@8` full/patch exposures in the treatment. Compare semantic continuation fields and advisory entries, excluding changing transport metadata (`work_batch_id`, task hash, watermark) from equality. Publish a bounded `full` or `patch` exposure linked to its previous content hash and current source watermark. Preserve exact evidence IDs, hashes, ranges, recovery recipes, freshness labels, and unresolved effects. A patch is a model-visible update, not a new historical authority.
4. **Recovery/reset.** Re-inject a full packet after a context cut that removed the baseline, worker-epoch loss/restart, or unresolved-effect recovery boundary; never pretend a missing prior message is still available. Baseline and delta events are append-only and idempotent; re-entry reproduces recorded bytes, while identity/hash mismatch fails closed. Keep volatile task/session state out of static instruction.
5. **Instrumentation.** Record each packet's exposure kind, prior/result hashes, component hashes and bytes, source watermark, work-batch identity, and reset reason. Existing provider-request and usage metrics remain the cost authority. Do not label local replay projections as quality/cost gains.

## Deterministic contract checks

Focused tests cover full→unchanged→changed→deletion→reset, exact replay after retry, corrupt base/hash rejection, stable provider instruction/tool prefix, required steering and full goal/scope preservation, indivisible call/result history, worker-loss/unknown-effect refusal, and verify admission after bounded review. Run unit/integration, lint, typing, and `git diff --check` before live dispatch. These checks establish safety, not value.

## Paired live value test, frozen before dispatch

- Use one clean revision, one attempt per arm/case, no retries or case substitution; preserve all terminal reasons and wire attempts.
- Same model, reasoning effort, provider routing, fixture/task bytes, task-input/iteration/output/wall limits, PTC review/cell/no-progress limits, verifier, sandbox image, and safety policy. Only the packet/review implementation differs from a frozen baseline revision or explicit compatibility switch. If a revision-level comparison cannot isolate the treatment, state the confound.
- Begin with four mechanism families: intact-worker delayed reuse, multi-cut worker-loss recovery, changed-source/no-change-shell/scoped-write freshness, and a review-heavy real coding task. Use fresh fixture variants, not another tuning route. The coding task's independent Harbor reward is quality authority.
- First frozen diagnostic dispatch: `routing`, `restart`, and `freshness` in `evals.verified_continuity`, one attempt each on `packet_baseline` and `packet_delta`, Luna/max, concurrency 6, common cached command image `sha256:c50fcbacd80c6e4b42e18fedf0f8f4bcb2c591ef9a04e4dba39e588e095d4b8e`. These are consumed development fixtures, so this is a mechanism gate, not held-out quality evidence. If it passes, freeze fresh variants and a DeepSWE coding pair before a broader claim.
- Second frozen dispatch: DeepSWE 1.1 `ipython-session-bundle-replay`, checked-in `notebook-ptc-memory.yaml` versus its byte-identical delta-switch clone `notebook-ptc-memory-delta.yaml`, OpenRouter `openai/gpt-5.6-luna` at `max`, 32,768 output reserve, 1B cumulative input, one attempt, zero retries, concurrency two across arms, identical pinned confirmation manifest and Harbor verifier. This task is previously used, so it is diagnostic regression/mechanism evidence rather than a fresh generalization cohort.
- After the observed treatment-only review block and repeated baseline review yields, freeze correction experiment E3 on two diagnostic DeepSWE tasks: `ipython-session-bundle-replay` (previous quality-regression/review case) and `actionlint-action-pinning-lint` (different language and earlier shared pass). Both arms use the same Luna/max and Harbor contract as E2; baseline remains the checked-in memory profile, treatment enables delta packets plus the revised one-decision review protocol and compact event-ID-addressed recent receipts. One attempt per arm/task, zero retries, concurrency four. This is a new treatment after a common diagnosed correction, not a selective repeat counted toward a held-out promotion gate. Stop and diagnose if either treatment gets unsupported completion or misses a baseline pass.
- E4 frozen correction validation keeps the same two diagnostic task IDs and Harbor/model/budget/retry contract, but advances the treatment after the E3 trace diagnosis: task-and-current-file-hash-scoped PTC catalog reuse across worker epochs, plus a ≤3,200-byte exact captured-range/artifact index in `work_batch_navigation@9` with capture-level deltas. A shared receipt/fingerprint fix classifies a completed nonzero validation command with unchanged workspace as a known failed attempt, never as passing verification. The compatibility baseline retains epoch-keyed PTC reuse and `@7` full navigation. One attempt per arm/task, zero retries, concurrency four, frozen source before dispatch. Repeat tasks remain diagnostic; require fresh diverse cases before broad promotion.
- Gate on correct completed-evidence outcomes, selective reads of changed/missing sources, zero unsupported acceptance or unresolved-effect bypass, retained-value use when the worker is live, and no repeat review loop without new evidence/verification outcome.
- Report each pair's official/independent quality, terminal status, review boundaries, first-call uncached tokens, full/patch bytes, model/tool/verification calls, total/cached/uncached/output/reasoning tokens, cost, active wall, source acquisition and same-version overlap. Shell/artifact exposure unmapped by receipts stays unknown.
- Do not claim value from fewer packets alone. Advance to a new diverse held-out DeepSWE cohort only if the live canary shows no quality/safety regression and lower paired uncached input and cost without more calls or avoidable rereads. If a pair stops at a different stage, report efficiency as descriptive, not causal.

## Stopping rule

Stop paid expansion on a safety, replay, prefix, accounting, or completed-evidence failure. Diagnose the trace and correct the shared seam before a new frozen canary. Do not tune or selectively retry the same completed cohort. Defaults remain unchanged until a fresh diverse live gate succeeds.
